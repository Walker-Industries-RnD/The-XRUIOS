2 - A Worker

A Worker

A worker is one system class running in its own process, exposing a curated set of capabilities the Manager can route to. This is where a new class from Barebones becomes a first-class part of the fleet. Every worker follows the shape of the Chrono worker, which is small enough to read in one sitting.

The layout

A worker is three files plus its system source:

src/workers/XRUIOS.Worker.<Class>/
├─ <Class>.csproj        compiles ONLY this class's source
├─ Program.cs            boot: bind context, init, run the secured host
└─ Capabilities.cs       the [SeaOfDirac] curated surface

src/systems/<Class>Class.cs   the class itself, written once and linked in

The isolation is the point: the worker <Compile Include>s just its own class file, so a breached Songs worker doesn't even contain Calendar's code. See 1 - The Model.

The .csproj

This is the real Chrono project, whole:

<Project Sdk="Microsoft.NET.Sdk.Web">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <OutputType>Exe</OutputType>
    <RootNamespace>XRUIOS.Worker.Chrono</RootNamespace>
    <AssemblyName>XRUIOS.Worker.Chrono</AssemblyName>
  </PropertyGroup>

  <ItemGroup>
    <Compile Include="../../systems/ChronoClass.cs" />
  </ItemGroup>

</Project>

Two things to notice:

  • Microsoft.NET.Sdk.Web, not the plain SDK: a worker hosts a MagicOnion/gRPC endpoint the Manager connects to.
  • No references here. Everything a worker needs is in src/workers/Directory.Build.props, which every worker under src/workers/ inherits automatically:
From Directory.Build.props Why
XRUIOS.SecureLayer (project) SecureWorkerHost, WorkerOcean, NotaryGuard, AuditTrail, WorkerEvents
XRUIOS.Contracts, XRUIOS.Core (projects) the context interface and the shim that reads XRUIOS_DATA_PATH and the worker's key
XRUIOS.Interfaces, YuukoProtocol.XRUIOS.Interfaces (projects) the shared records and the file layer the system classes use
XRUIOS.Interpreter (project) what a capability does on this operating system (see 13 - XRUIOS.Interpreter)
EclipseProject.dll the [SeaOfDirac] attribute and the encrypted transport
PariahCybersecurity.dll SecureData, the anti-tamper watchdog
KeeperOfTomes.dll, Secure Store.dll storage the classes depend on
the Barebones package set so any single class compiles (Ical.Net, GeoCoordinate, and so on)

If your class needs a package no other class does, add it to that class's own .csproj rather than the shared props. Keep the shared set to what every class needs.

The capability surface

Capabilities are methods marked [SeaOfDirac]. WorkerOcean scans the assembly for them, and the Manager routes a call by the capability name. Keep the surface curated: the cross-program calls, not every public method. This is the real Now capability from Chrono:

using EclipseProject;
using XRUIOS.Barebones;

namespace XRUIOS.Worker.Chrono
{
    public static class ChronoCapabilities
    {
        [SeaOfDirac("Chrono.Ping", new[] { "input" }, typeof(string), typeof(string))]
        public static string Ping(string input) => "XRUIOS.Worker.Chrono: " + input;

        [SeaOfDirac("Now", new[] { "tz" }, typeof(string), typeof(string))]
        public static string Now(string tz = "") { /* ... */ }
    }
}

The attribute is [SeaOfDirac(name, argumentNames, returnType, argumentTypes...)]. A few rules that come from how WorkerOcean works:

  • Argument names are bound by name. The caller sends { "tz": "..." }, and the value goes to the parameter called tz. A parameter with a C# default value may be left out, so you can add an optional argument later without breaking existing callers.
  • Integers travel as long. Declare a count as long in the attribute and the method, not int.
  • Async is supported. Return Task or Task<T>.
  • Return plain strings (or simple DTOs). Lists use ; between rows and | between fields, so any client can read them without sharing your internal types.
  • Throwing is fine. The message reaches the app as a failed call. Use it for bad input, for example throw new ArgumentException("Ask needs a prompt.").
  • Names must be unique across the fleet. The broker routes to the first worker that announces a name. Every worker also exposes <Worker>.Ping so it can be probed on its own.

Boot (Program.cs)

This is the real Chrono Program.cs. Every worker boots the same way: take the context the Manager handed it, do its own one-time setup, then run the secured host.

using System.Reflection;
using XRUIOS.Interfaces;

// Take the Manager's context (paths and this worker's own key) from the environment.
global::XRUIOS.Barebones.XRUIOS.BindFromEnvironment();

// This worker's OWN setup. The Manager never reaches into a worker's data.
if (File.Exists(Path.Combine(global::XRUIOS.Barebones.XRUIOS.DataPath, "Chrono", "Chrono.json")))
    await global::XRUIOS.Barebones.ChronoClass.LoadDateData();

const string ServerName = "XRUIOS.Worker.Chrono";

await SecureWorkerHost.Run(
    serverName: ServerName,
    capabilityAssembly: Assembly.GetExecutingAssembly());

There is no gate argument and no guard argument. Run uses ManagerOnlyGate and builds the NotaryGuard for the worker's own folder. It also hardens the process, checks the Manager-signed baseline, opens the audit log, and publishes the worker's address. The full order is in 5 - XRUIOS.Worker. Do not pass AllowAllPermissionGate; it is obsolete.

Adding a worker, step by step

This example adds a made-up Greeter worker with one capability.

1. The system class (src/systems/GreeterClass.cs). Plain code with no XRUIOS types:

namespace XRUIOS.Barebones
{
    public static class GreeterClass
    {
        public static string Greet(string name, string language) =>
            language == "fr" ? $"Bonjour, {name}" : $"Hello, {name}";
    }
}

2. The project (src/workers/XRUIOS.Worker.Greeter/Greeter.csproj): copy Chrono's project and change the names and the Compile Include to ../../systems/GreeterClass.cs.

3. The capabilities (Capabilities.cs):

using EclipseProject;
using XRUIOS.Barebones;
using XRUIOS.Interfaces;

namespace XRUIOS.Worker.Greeter
{
    public static class GreeterCapabilities
    {
        [SeaOfDirac("Greeter.Ping", new[] { "input" }, typeof(string), typeof(string))]
        public static string Ping(string input) => "XRUIOS.Worker.Greeter: " + input;

        [SeaOfDirac("Greet", new[] { "name", "language" }, typeof(string), typeof(string), typeof(string))]
        public static string Greet(string name, string language = "en")
        {
            // Who asked? Set by the Manager, so the app cannot fake it.
            string who = WorkerCall.CallerAppId ?? "unknown";
            WorkerEvents.Publish("GreetingMade", $"{{\"for\":\"{name}\",\"by\":\"{who}\"}}");
            return GreeterClass.Greet(name, language);
        }
    }
}

4. The boot (Program.cs): the same as Chrono's, with ServerName = "XRUIOS.Worker.Greeter". Drop the LoadDateData lines unless your class needs setup.

5. Register it with the Manager. Two edits outside the worker:

  1. Add ("Greeter", PermissionGroup.Interface) to WorkerCatalog.Defs in XRUIOS.Manager/WorkerCatalog.cs, so the Manager finds, launches and supervises it.
  2. Add the project to XRUIOS.slnx.

6. Build, approve, restart.

dotnet build src/workers/XRUIOS.Worker.Greeter
XRUIOS.Manager baseline Greeter
XRUIOS.Manager stop
XRUIOS.Manager start

The baseline step is not optional. The Manager will not launch a folder that has no signed baseline, and the worker will not run without one.

7. Grant it to an app. Add "Greet" to that app's capability list, in AppCatalog.cs for a built-in app or in the manifest of a third-party app. Add "GreetingMade" to the app's events if it should receive the event (the grant is Events.GreetingMade). Ungranted names are denied at the broker before they reach the worker.

8. Check it. Add Greeter to the list of workers in XRUIOS.Diagnostics so it gets a ping probe, then run the harness (see 6 - The Diagnostics Harness).
