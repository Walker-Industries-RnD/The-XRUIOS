4 - A Desktop App

A Desktop App

A desktop app is the CMD app with a window on top. The broker client is UI-framework-agnostic, so the rule is simple: the connection lives in one small place, the UI calls it, and no XAML ever talks to a worker. The apps that ship with the XRUIOS are written with OpenSilver (XAML) hosted in a Photino window. This page shows that setup first, because it is the one in the repo, and then the same idea with WPF.

The apps that ship: OpenSilver and Photino

Every UI app under src/apps has the same shape:

src/apps/XRUIOS.App.<Name>/
├─ XRUIOS.App.<Name>/            the OpenSilver UI (App.xaml, MainPage.xaml)
├─ XRUIOS.App.<Name>.Controls/   this app's custom controls
├─ XRUIOS.App.<Name>.Photino/    the desktop window (the production shell)
├─ XRUIOS.App.<Name>.Browser/    browser host
└─ XRUIOS.App.<Name>.Simulator/  WPF simulator for a fast dev loop

They all reference XRUIOS.Apps.Shared, which holds the broker connection, the widget chrome and the holes (see 15 - XRUIOS.Aether and Apps.Shared). The app project itself references only OpenSilver and XRUIOS.Apps.Shared:

<ItemGroup>
  <PackageReference Include="OpenSilver" Version="3.3.3" />
  <ProjectReference Include="..\..\XRUIOS.Apps.Shared\XRUIOS.Apps.Shared.csproj" />
</ItemGroup>

The window

The Photino project is a few lines. This is the Time app:

var window = new PhotinoWindow()
    .SetTitle("Time")
    .SetSize(1920, 1080)
    .SetResizable(true)
    .Center()
    .ConfigureOpenSilver<App>()
    .Load("wwwroot/index.html");

window.WaitForClose();

Fullscreen apps (Calendar, Gallery, ThemeEditor, Time, Weather, WorldEvents) look like this. Widgets (AppLauncher, Clipboard, Keyboard, Notifications, PocketPal, Power, VolumeManager) are small, chromeless and always on top, and their MainPage wraps its content in WidgetChrome.

The page connects once, then calls a hole

public partial class MainPage : Page
{
    public MainPage()
    {
        InitializeComponent();

        Loaded += async (_, _) =>
        {
            // One connection for the whole app. The name must match the app's entry in the Manager.
            await AppShell.InitializeAsync("XRUIOS.App.Time");

            // A hole is one line: it calls the Now capability and parses the reply.
            string now = await TimeSource.NowAsync();
            ActiveCountLine.Text = now;
        };
    }
}

AppShell.InitializeAsync calls WorkerBroker.ConnectAsync, which finds credentials from the environment, a dev creds file, or enrollment, exactly as in 3 - A CMD App. The XAML never sees the broker, never holds a password and never names a worker.

Live updates

Instead of polling, subscribe to events the app was granted. Keep the stream while the page is open and dispose it when the page goes away. Callbacks arrive on a background thread, so hand the work back to the UI thread.

using XRUIOS.Apps.Shared;
using XRUIOS.Apps.Shared.Holes;
using XRUIOS.Interfaces;     // XruiosEventStream
using XRUIOS.Interpreter;    // AlarmInfo, XruiosEventNames

private XruiosEventStream? _alarms;

Loaded += async (_, _) =>
{
    await AppShell.InitializeAsync("XRUIOS.App.Time");
    _alarms = EventFeed.On<AlarmInfo>(XruiosEventNames.AlarmFired,
        alarm => Dispatcher.BeginInvoke(() => ShowAlarm(alarm)));
};

Unloaded += async (_, _) => { if (_alarms != null) await _alarms.DisposeAsync(); };

The Time app is granted Events.AlarmFired in AppCatalog. An app that is not granted an event simply never receives it.

Making a new app

  1. Generate it the way src/apps/README.md describes (dotnet new opensilverapp --usePhotino), then reference XRUIOS.Apps.Shared.
  2. Add a hole to XRUIOS.Apps.Shared/Holes/ if the capability you need has none yet (one small file).
  3. Add the app to AppCatalog.cs with the capabilities and events it uses:
new("XRUIOS.App.MyApp", Ui("MyApp"), new[] { "Now", "ListAlarms" }, new[] { XruiosEventNames.AlarmFired }),

Ui("MyApp") makes the Manager look for the executable XRUIOS.App.MyApp.Photino. Every UI app also receives ThemeChanged so it can repaint.

  1. Build, then approve the app's folder: XRUIOS.Manager baseline XRUIOS.App.MyApp.
  2. Start the Manager and run the app. It enrolls itself.

An app that is not part of this repo skips step 3 and ships a manifest for install-app instead (see 8 - Building a XRUIOS App).

WPF or Avalonia

The same idea works without OpenSilver. Reference XRUIOS.SecureLayer (and EclipseProject.dll) like the CMD app does, and put the connection in a service the view model uses.

<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>WinExe</OutputType>
    <TargetFramework>net10.0-windows</TargetFramework>
    <UseWPF>true</UseWPF>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
  <ItemGroup>
    <ProjectReference Include="..\XRUIOS.SecureLayer\XRUIOS.SecureLayer.csproj" />
  </ItemGroup>
  <ItemGroup>
    <Reference Include="EclipseProject"><HintPath>..\..\libs\EclipseProject.dll</HintPath></Reference>
  </ItemGroup>
</Project>

The service. The credentials step is the same three-way lookup as the CMD app, ending in enrollment:

using XRUIOS.Interfaces;

public sealed class XruiosClient
{
    private EclipseSecureClient? _mgr;

    public async Task ConnectAsync()
    {
        // Environment variables first; otherwise ask the running Manager. The name is the one in the manifest.
        string? id  = Environment.GetEnvironmentVariable("XRUIOS_APP_ID");
        string? psk = Environment.GetEnvironmentVariable("XRUIOS_APP_PSK");
        string? addr = Environment.GetEnvironmentVariable("XRUIOS_BROKER_ADDR");
        if (id is null || psk is null || addr is null)
        {
            var prov = await XruiosEnrollment.EnrollAsync("mydesktopapp");
            (id, psk, addr) = (prov.AppId, prov.PskBase64, prov.BrokerAddress);
        }

        _mgr = await EclipseSecureClient.ConnectAsync(addr, "mydesktopapp", Convert.FromBase64String(psk), identity: id);
    }

    public Task<string> GetDayAsync(string day) =>
        _mgr!.InvokeAsync<string>("GetEvents", new() { ["day"] = day });

    public Task<string> AddAsync(string day, string summary) =>
        _mgr!.InvokeAsync<string>("AddEvent", new() { ["day"] = day, ["summary"] = summary });
}

The view model binds to it. await brings you back to the UI thread, so the only rule is not to block on the connection:

public async Task LoadAsync(string day)
{
    string raw = await _client.GetDayAsync(day);                    // off the UI thread
    Events.Clear();
    foreach (var line in raw.Split(';', StringSplitOptions.RemoveEmptyEntries))
        Events.Add(line.Trim());                                    // back on it
}

Three things a window must respect

  • Connect once, async, off the constructor. Do the handshake in OnStartup (WPF) or Loaded (OpenSilver), show a "connecting" state, and enable the UI only when it is up. A failed handshake is a normal state ("XRUIOS is locked, log in first"), not a crash. Do not swallow it silently either: show it.
  • A denied capability is a UI affordance, not a swallowed exception. If the app was not granted DeleteEvent, do not render a delete button. The broker refuses it regardless, but a good app does not offer what it cannot do.
  • The password comes from the Manager. Do not bake a secret into the app or its settings. Ship the executable with none, and let the Manager hand it over.
