5 - Permission Catalog

Permission Catalog

Every capability that exists today, by group and worker, with its arguments and which built-in apps hold it. A grant is simply the capability's name, for example GetEvents. There is no Group.Worker: prefix in the code: the Manager finds the worker by looking for the first one that announces that name, so capability names must be unique across all workers.

Events are granted the same way, with the prefix Events., for example Events.AlarmFired. Every UI app also holds Events.ThemeChanged.

Every worker also answers <Worker>.Ping (for example Chrono.Ping), a health probe. Only the diagnostics harness is granted these.

All 28 workers now have real capabilities: 140 in total. The ones in the tables below marked "none" are not held by any built-in app yet; an app gets them through its manifest (see Granting at the end). Do note, another layer exists as well (The XRUIOS.Barebones) within the project, which is responsible for essentially a CRUD style language for getting and acting on functions, bringing the total count of functions way about the 400+ line.

Replies are plain text so any client can read them. List replies use ; between rows and | between fields, for example ListAlbums returns id|title|count;id|title|count. In any text that came from a user, a | or ; is shown as / or , so a row can never be split by what is inside it.

Calls are limited by the permission store, not by the worker

XRUIOS.Permission allows 100 permission checks per minute per app. The Manager remembers each (app, capability) answer for 15 seconds, so an app can call the same capability as fast as it likes. An app that uses very many different capabilities in a minute can still reach 100 distinct checks; it then gets a plain "could not be completed, try again shortly" message instead of a crash.

Granting

Grants are not written by hand in the Manager any more. They come from an app's manifest: a name, the executable that may enroll as it, its capabilities and its events. Built-in apps have theirs in AppCatalog.cs. A third-party app ships a JSON file:

{
  "name": "MyCalendarWidget",
  "exe": "C:\\Apps\\MyCalendarWidget\\MyCalendarWidget.exe",
  "capabilities": [ "GetEvents", "ListCalendars" ],
  "events": [ "AlarmFired" ]
}

XRUIOS.Manager install-app manifest.json

At every Manager start, each app is granted exactly what its manifest lists. A capability that an earlier version granted and the new manifest no longer lists is revoked. Anything not granted is denied at the broker before it reaches a worker. See 3 - Capabilities and Sharing for a worked example, and 8 - Building a XRUIOS App for complete apps.
