9 - XRUIOS.SecureLayer

What is it?

XRUIOS.SecureLayer is the library that the Manager, every worker, and every app share. It holds the encrypted channel, the capability dispatcher, the tamper checks and the audit log. Every file in it is listed here, grouped by job. For how these pieces connect to the Manager and workers, see 14 - The Chain.

The channel (how two programs talk)

EclipseSecureClient

The client side of the Eclipse channel. One call to ConnectAsync does the whole enrollment, Kyber handshake and transcript check. After that, InvokeAsync<T>(capability, args) sends an encrypted call and decrypts the reply.

  • Calls on one client are serialized (Eclipse numbers every message, so two calls cannot be in flight on one session).
  • If the server says the session expired (idle), the client handshakes again and retries once. The server rejected the call before running anything, so that is safe.
  • InvokeRawAsync returns the decrypted result bytes without deserializing. The Manager uses it to relay a worker's reply to an app without ever needing the reply's type.
  • For a Manager-to-worker connection the caller passes the Manager's private key, and the client signs its own id with it. That signature travels in place of the client name.

SecureWorkerHost

Hosts a worker (Run) or the Manager's broker (RunBrokerAsync) behind the Eclipse protocol. It contains PlaguesDiracService, which implements the five Eclipse calls: enroll, begin handshake, finish handshake, invoke, finish.

  • On a worker, enrollment checks the Manager's signature over the client id, and only signed clients may handshake.
  • A session the server no longer knows throws RpcException(Unauthenticated). That distinct status is what tells EclipseSecureClient it is safe to reconnect.
  • RunBrokerAsync is the same host with a per-app PSK lookup and a router instead of a local dispatcher.
  • HardenProcess blocks injection and watches for a debugger. The Manager calls it too.

PqcGate

A single lock around the post-quantum crypto calls (Kyber and Dilithium). Pariah's primitives are not safe to call from several threads at once, which showed up as failed handshakes under parallel load. Only the crypto step is held, never a network round trip.

XruiosEnrollment and AppProvisioning

How an app that is its own executable gets credentials. EnrollAsync(appName) connects to the Manager's local control pipe (xruios-manager-control) and asks to be enrolled. The Manager checks which process is calling and which folder it runs from before answering. The answer is an AppProvisioning: the app id, its PSK (base64) and the broker address. Nothing is stored on disk. The pipe check is described in 8 - XRUIOS.Manager.

WorkerAnnouncement

What a worker tells the Manager at startup: its name, address, capability list, Kyber public key and process id. Only public information. The private key never leaves the worker.

Utils (SecureStore)

A small key/value store of JSON files under %TEMP%\SECURE_STORE<username>. It is not encrypted and holds no secrets. It carries each worker's address and announcement, and the Manager's broker address. The first time a process uses it, the folder is created and restricted to the current account: on Windows the inherited permissions are removed and only that account is allowed (for the folder and everything created in it), and on Linux the folder is mode 700 and files are mode 600. A folder left by an older build is tightened the same way. This keeps other accounts out. It does not stop a program running as the same account, which is why nothing secret is stored here.

The dispatcher (what a worker does with a call)

WorkerOcean

The worker-side capability table. It scans the worker's assembly for [SeaOfDirac] methods, then on each call:

  1. Asks the gate if the session is allowed (ManagerOnlyGate by default).
  2. Handles the reserved names (__xruios.events for the event pump, __xruios.audithead for audit anchoring). These are never announced, so the broker cannot route an app to them.
  3. Strips any argument starting with __xruios., except the caller stamp, and binds the rest by name. A parameter with a C# default value may be left out, so a capability can gain an optional argument without breaking older callers.
  4. Runs the method (async methods are awaited), writes an audit entry, and encrypts the result.

Permissions

IPermissionGate is the worker's second wall. ManagerOnlyGate is the default: it answers true only for a session whose enrollment carried a valid Manager signature (SecureWorkerHost.IsVerifiedManagerSession). CapabilityAllowListGate permits a fixed list. AllowAllPermissionGate is [Obsolete] and is only for throwaway tests.

WorkerCall

WorkerCall.CallerAppId gives a capability the id of the app that made the current call (for example app:XRUIOS.App.PocketPal). The Manager stamps it, so an app cannot lie about it.

PublicAcc

Only the PublicAccount struct (name, last check, OS folder). The old IPublicAcc service is gone.

Integrity (is this folder what the Manager approved?)

BaselineSeal

Signing and checking of a folder's file tree.

  • Digest makes a canonical SHA-256 over the sorted (path, hash) pairs.
  • SignAsync signs that digest with the Manager's Dilithium key. VerifyAsync checks it with the Manager's public key.
  • Relativize rewrites paths relative to the folder before comparing. The same folder can be spelled differently by two processes (a long path against an 8.3 short name), and comparing absolute paths caused false tamper failures.
  • TreeEnv and SignatureEnv are the two environment variables the Manager uses to hand a worker its baseline.

NotaryGuard

The worker's tamper check. AdoptSignedBaselineAsync accepts a baseline only if the Manager's signature verifies; the verified tree is then held in memory. VerifyOrExitAsync hashes the folder and exits with code 44 on any difference, and StartPeriodic repeats it every 30 seconds. The old trust-on-first-use behaviour only remains for XRUIOS_DEV_STANDALONE=1 runs, which have no Manager to ask.

Records (what happened, and who heard about it)

AuditTrail

An append-only log in which every line carries the previous line's MAC and its own HMAC-SHA256 over its fields. Editing, reordering or deleting a line breaks the chain from that point on.

  • An entry holds: sequence number, time, actor, action, target, ok, detail, previous MAC, and its own MAC.
  • ForWorker builds a worker's log from XRUIOS_DATA_PATH and its own key (<Data>/Audit/<name>.log). With no key (a dev standalone run) there is no log.
  • The log key is KeyFrom(baseKey), an HKDF derivation, so the audit key differs from the key that encrypts the worker's data.
  • Append opens the file under an exclusive write handle and reads the last entry from the end of the file each time, so more than one process can write the same log. If the file stays busy it gives up quietly rather than fail a call.
  • Head returns the newest entry's sequence number and MAC. The Manager records these as "anchors" in its own log, which is how an audit run notices entries cut off the end of a worker log.
  • Verify walks the chain and names the first bad line.

XruiosEvents

The shared event types. XruiosEvent is one thing that happened (a sequence number, the source worker, a name, a text payload, a time). XruiosEventProtocol holds the shared names: Events.Poll (what an app calls), __xruios.events (what the Manager calls on a worker), and the rule that receiving an event needs the grant Events.<Name>. WorkerEvents is the worker's own bounded log (512 entries) with an epoch id, so a restarted worker makes the Manager read from the start of the new log instead of an old cursor.

XruiosEventStream

The app side of events. It keeps a second session open under the id <appId>#events and long-polls Events.Poll, so waiting for events never blocks the app's normal calls. It reconnects with backoff (1 to 15 seconds) and resumes from its cursor. A handler that throws does not stop the stream.
