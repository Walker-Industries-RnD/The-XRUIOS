The Big Map

Every file that matters, in one picture, and how they talk to each other. Read it top to bottom: an app at the top asks for something, and the request travels down through the Manager to a worker and its data.

How to read the arrows:

  • A plain arrow is one file calling another.
  • A thick arrow is an encrypted connection between two programs (post-quantum key exchange, then AES-256-GCM).
  • A dotted arrow is reading or writing something on disk.
  • A box with <br/> text is a file; the second line says what it does.

The smaller pictures that show one story at a time (startup, one call, enrollment, events, approval, audit, keys) are on 14 - The Chain. This page is the whole thing at once.

Reading it in five sentences

  1. Apps never touch workers. An app page calls a hole, the hole calls WorkerBroker, and EclipseSecureClient carries the call over an encrypted connection to the Manager's broker. The app and the worker only ever meet inside the Manager.
  2. The Manager decides. BrokerRouter asks PermissionService (which remembers answers for 15 seconds because the permission library rate-limits to 100 checks a minute), picks the worker that announced the capability, relays it through a warm session, and writes both ends to the audit log.
  3. Workers are launched, not trusted. WorkerSupervisor only starts a worker whose folder matches a baseline the Manager signed, hands it a password, its own key and the signed baseline, and the worker checks itself again every 30 seconds.
  4. Every key comes from one password. LoginService unlocks the master key; KeyAuthority derives a separate key for each purpose (permissions, identity, app list, certificates, audit, and one per worker), so no store opens with another's key.
  5. The Interpreter is the only code that touches the machine. Capabilities ask it to change the volume, show a notification or open an app; on Windows and Linux it calls the OS, and under an Aether Engine shell it sends events for the engine to draw.
